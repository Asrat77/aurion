# Animation Improvement Plans — AURION frontend

Generated by the `improve-animations` skill (Emil Kowalski). Audit of the Next.js
frontend's motion surface (all CSS/Tailwind; no motion library). Product
personality: **luxury / premium** → crisp, restrained motion, minimal bounce.

Motion values are pulled verbatim from the skill's `AUDIT.md` — do not approximate.

| # | Title | Severity | Category | Status |
|---|-------|----------|----------|--------|
| 001 | Motion-token foundation, kill `transition: all` | HIGH | Easing/Perf | DONE |
| 002 | Button press feedback + hover gating | HIGH/MED | Physicality/A11y | DONE |
| 003 | Toasts: real entrance, interruptible | HIGH | Interruptibility | DONE |
| 004 | Drawer curve, modal + dropdown + card | MED | Physicality/Easing | DONE |
| 005 | Global `prefers-reduced-motion` guard | MED | Accessibility | DONE |

## Recommended execution order

**001 → 002 → 003 → 004 → 005.** 001 introduces the tokens every later plan
references; 005 must come last so the guard covers all the motion added before it.

## Dependencies

- 002, 004 depend on the motion tokens from **001**.
- 005 depends on **001–004** (it nulls the transforms they introduce).
- 003 is independent but shares the rAF mount-flag pattern reused in 004.

## Not planned (noted, not fixed)

- **Missed opportunity**: product-grid stagger (30–80ms) on `/store` — additive
  polish, LOW leverage. Consider later.
- **Missed opportunity**: cart-badge count change teleports — a subtle pulse
  would help, but LOW leverage.
- Nav-link `transition-colors` — correct as-is (color change → ease is fine).
